[Normal] Với vai trò Content Admin, tôi muốn tạo job tự động từ tên món để giảm nhập tay.
[List Bullet] AC: Theo dõi được từng bước pipeline
[List Bullet] AC: Job lỗi có mã lỗi và retry
[List Bullet] AC: Output luôn ở trạng thái chưa xuất bản
[Heading 2] US-DISH-03 — Xem evidence theo trường
[Normal] Với vai trò Reviewer, tôi muốn xem evidence theo trường để đánh giá nguồn.

[List Bullet] AC: Có confidence và xung đột
[List Bullet] AC: Có thể chọn giá trị hoặc nhập thủ công
[Heading 2] US-DISH-04 — Duyệt món

[Heading 1] 12. Yêu cầu API ở mức BA
[Heading 2] 12.1 Chuẩn response và lỗi
[List Bullet] ID sử dụng UUID; thời gian ISO-8601 UTC.
[List Bullet] Danh sách dùng cursor pagination cho dữ liệu lớn.
[List Bullet] Validation lỗi trả fieldErrors có code, field và message.
[List Bullet] 409 cho xung đột phiên bản/slug; 422 cho business rule; 403 cho thiếu quyền; 404 không tiết lộ bản ghi ngoài phạm vi.
[List Bullet] Admin API trả warnings riêng với errors để UI cho phép quyết định có kiểm soát.
[List Bullet] Idempotency-Key bắt buộc cho create import job, approve và random nếu client có retry.

[Heading 1] Phụ lục A — Definition of Ready
[List Bullet] User story có actor, value và acceptance criteria.
[List Bullet] Business rules liên quan đã được đánh mã.
[List Bullet] Wireframe hoặc mô tả UI đủ rõ.
[List Bullet] Data field, validation và permission đã chốt.
[List Bullet] API dependency và nguồn dữ liệu đã xác định.
[List Bullet] Không còn câu hỏi mở chặn phát triển.
[Heading 1] Phụ lục B — Definition of Done
[List Bullet] Code review và test tự động đạt.
[List Bullet] Migration/index/seed có rollback.
[List Bullet] API contract và error codes được cập nhật.
[List Bullet] Audit, metric và log không chứa dữ liệu nhạy cảm.
[List Bullet] QA pass acceptance + edge cases.
[List Bullet] Admin UI có loading/empty/error/permission states.
[List Bullet] Tài liệu vận hành và rollback được bàn giao.

[List Bullet] Catalog có code ổn định; tên/description có thể dịch và thay đổi mà không phá dữ liệu.

[Heading 1] 10. API đề xuất cho NestJS
[Heading 2] Yêu cầu contract
[List Bullet] Mọi PATCH nhận profile_version và idempotency_key.
[List Bullet] Response trả saved_at, profile_version, current_step, next_step, field_errors.
[List Bullet] Server là nguồn validation cuối; client không tự quyết trạng thái COMPLETED.
[List Bullet] Catalog trả version/ETag và hỗ trợ cache; ID không bị tái sử dụng.
[List Bullet] Complete thực hiện transaction hoặc cơ chế bù để không có COMPLETED nhưng thiếu dữ liệu bắt buộc.

[List Bullet] OnboardingModule tách controller/service/repository/catalog/policy/analytics adapter.
[List Bullet] DTO theo từng bước, không dùng một DTO khổng lồ cho toàn flow.
[List Bullet] Upsert idempotent theo user_id + onboarding_version; optimistic locking bằng profile_version.
